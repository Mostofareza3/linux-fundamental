Linux User and Group Management

একটা Linux system-এ কে কী করতে পারবে — পুরোটাই ঠিক হয় user আর group দিয়ে। এই lab-এ তুমি user বানাবে, group বানাবে, primary আর supplementary group-এ user বসাবে, আর দরকার হলে কোনো account সাময়িকভাবে বন্ধ (lock) করে আবার খুলবে।

এই lab শেষে যা পারবে

  • নতুন user account বানাবে।
  • Group বানাবে আর সেটার সদস্য দেখবে।
  • Primary আর supplementary group — দুটোর পার্থক্য বুঝে user বসাবে।
  • Account lock করে সেটা verify করবে, আবার unlock করবে।
  • System-এর সব user-এর তালিকা দেখবে।
সাবধানতা

এই lab-এর সব command sudo দিয়ে চলে, অর্থাৎ system-এ আসল পরিবর্তন হয়। তাই কাজটা নিজের practice VM, WSL, বা ফেলে দেওয়া যায় এমন একটা VPS-এ করো — কোনো production server-এ নয়। শেষে পরিষ্কার করার command গুলোও দেওয়া আছে।

আগে দুটো ধারণা পরিষ্কার করে নাও

Primary group

প্রতিটা user-এর ঠিক একটা primary group থাকে — বাধ্যতামূলক। তুমি যখন কোনো file বানাও, সেই file-এর group হয় তোমার primary group। User বানানোর সময় Linux সাধারণত username-এর নামেই একটা group বানিয়ে সেটাকে primary group করে দেয়।

Supplementary group

এগুলো অতিরিক্ত group — primary-র বাইরে বাড়তি access পাওয়ার জন্য। একজন user একসাথে অনেকগুলো supplementary group-এ থাকতে পারে। এই তালিকাটা /etc/group file-এ রাখা থাকে।

বাস্তব উদাহরণ

একটা কোম্পানিতে নতুন software developer এলো। তার primary group হলো developers — সে যা যা বানাবে সব ঐ group-এর হবে। কিন্তু তার project documentation-এও ঢোকা দরকার, তাই তাকে docs group-এ supplementary হিসেবে যোগ করা হলো। এতে সে নিজের department-এ থেকেও অন্য জায়গার access পেল।

Account lock করা মানে কী

Lock করলে user আর password দিয়ে login করতে পারে না — কিন্তু তার account, file, কোনো কিছুই মুছে যায় না। কেউ লম্বা ছুটিতে গেলে বা সাময়িকভাবে access বন্ধ করতে হলে account মুছে না ফেলে lock করাই ঠিক কাজ।

যে দৃশ্যটা আমরা বানাবো

ধরো Poridhi নামের একটা টিম। আমরা চারজন user বানাবো — nabil, minhaz, yasin, fazlul — আর একটা group বানাবো poridhi-minions। তারপর nabil-কে ঐ group-এ primary হিসেবে বসাবো, আর বাকি তিনজনকে supplementary হিসেবে।

যা বানাতে যাচ্ছি
group: poridhi-minions
│
├── nabil     ← primary group এটাই
├── minhaz    ← supplementary (primary: minhaz)
├── yasin     ← supplementary (primary: yasin)
└── fazlul    ← supplementary (primary: fazlul) → পরে lock/unlock

অনুশীলন

User বানানো

লক্ষ্য: Poridhi-র চারজন কর্মীর জন্য account বানানো।

bash
$ sudo useradd nabil
$ sudo useradd minhaz
$ sudo useradd yasin
$ sudo useradd fazlul

ব্যাখ্যা: useradd নতুন user বানায়। কিছু না বললে system নিজেই একটা UID দেয় (সাধারণত 1000 থেকে শুরু), আর username-এর নামেই একটা group বানিয়ে সেটাকে primary group করে দেয়।

যাচাই করো:

bash
$ id nabil
output
uid=1000(nabil) gid=1000(nabil) groups=1000(nabil)
তোমার সংখ্যাগুলো আলাদা হতে পারে — system-এ আগে থেকে কতজন user আছে তার উপর নির্ভর করে।

এই output তিনটে কথা বলছে:

  • uid=1000 — nabil-এর নিজস্ব User ID।
  • gid=1000(nabil) — তার primary group, নাম nabil।
  • groups=1000(nabil) — সে আর কোনো group-এ নেই। কোনো supplementary group নেই।
useradd না adduser?

Debian/Ubuntu-তে adduser নামে আরেকটা command আছে — সেটা প্রশ্ন করে করে home directory, password সব সেট করিয়ে নেয়। আর useradd হলো নিচের স্তরের, চুপচাপ কাজ সেরে ফেলে। এই lab-এ useradd ব্যবহার করছি কারণ প্রতিটা ধাপ আলাদা করে দেখা যায়।

Group বানানো

লক্ষ্য: টিমের জন্য poridhi-minions group তৈরি করা।

bash
$ sudo groupadd poridhi-minions

ব্যাখ্যা: Group থাকার কারণেই একই permission বারবার প্রত্যেক user-কে আলাদা করে দিতে হয় না — group-কে একবার দিলেই সবার হয়ে যায়।

যাচাই করো:

bash
$ getent group poridhi-minions
output
poridhi-minions:x:1004:
গঠন: group-নাম : x : GID : সদস্যরা — শেষের ঘরটা এখন খালি, কারণ এখনো কেউ যোগ হয়নি।

Primary group বদলানো

লক্ষ্য: nabil-এর primary group করে দেওয়া poridhi-minions।

bash
$ sudo usermod -g poridhi-minions nabil

ব্যাখ্যা: usermod দিয়ে বিদ্যমান user-এর সেটিং বদলানো যায়। ছোট হাতের -g মানে — primary group টা বদলে দাও।

যাচাই করো:

bash
$ id nabil
$ groups nabil
output
$ id nabil
uid=1000(nabil) gid=1004(poridhi-minions) groups=1004(poridhi-minions)

$ groups nabil
nabil : poridhi-minions
আগে gid ছিল 1000(nabil), এখন হয়ে গেছে 1004(poridhi-minions)।

Supplementary group-এ user যোগ করা

লক্ষ্য: minhaz, yasin, fazlul-কে poridhi-minions-এ বাড়তি সদস্য হিসেবে যোগ করা।

bash
$ sudo usermod -aG poridhi-minions minhaz
$ sudo usermod -aG poridhi-minions yasin
$ sudo usermod -aG poridhi-minions fazlul

ব্যাখ্যা: -aG-তে দুটো জিনিস — -G মানে supplementary group ঠিক করা, আর -a মানে append, অর্থাৎ আগের group গুলো রেখে নতুনটা যোগ করা।

-a বাদ দিলে সর্বনাশ

-a ছাড়া শুধু -G লিখলে user-এর আগের সব supplementary group মুছে গিয়ে শুধু নতুনটা থাকবে। কেউ sudo group-এ ছিল আর তুমি -a ভুলে গেলে — সে sudo access হারাবে। তাই -aG একসাথেই টাইপ করার অভ্যাস করো।

যাচাই করো:

bash
$ id minhaz
$ groups minhaz
$ getent group poridhi-minions
output
$ id minhaz
uid=1001(minhaz) gid=1001(minhaz) groups=1001(minhaz),1004(poridhi-minions)

$ groups minhaz
minhaz : minhaz poridhi-minions

$ getent group poridhi-minions
poridhi-minions:x:1004:minhaz,yasin,fazlul

minhaz-এর primary group এখনো minhaz (gid=1001) — সেটা বদলায়নি। শুধু poridhi-minions তার তালিকায় যোগ হয়েছে।

nabil কোথায় গেল?

খেয়াল করো, getent group poridhi-minions-এর সদস্য তালিকায় nabil নেই — অথচ nabil তো এই group-এই আছে!

কারণটা হলো, /etc/group-এর ঐ শেষ ঘরটায় শুধু supplementary সদস্যদের নাম লেখা হয়। nabil-এর ক্ষেত্রে poridhi-minions হলো primary group, আর সেই তথ্যটা রাখা আছে /etc/passwd file-এ তার GID হিসেবে। দুই জায়গায় দুই রকম তথ্য — তাই id nabil দিলে ঠিকই দেখা যায়।

Account lock করা

লক্ষ্য: fazlul লম্বা ছুটিতে — তার login সাময়িকভাবে বন্ধ করা।

bash
$ sudo usermod -L fazlul

ব্যাখ্যা: বড় হাতের -L মানে Lock। ভেতরে যা ঘটে — /etc/shadow-এ রাখা password hash-টার সামনে একটা ! বসিয়ে দেওয়া হয়। ফলে কোনো password-ই আর মেলে না, তাই login হয় না। কিন্তু user-এর file, home directory সব অক্ষত থাকে।

যাচাই করো:

bash
$ sudo passwd -S fazlul
output
fazlul L 02/10/2025 0 99999 7 -1

ঘরগুলোর মানে:

যা দেখছোমানে
LAccount locked — login করা যাবে না
02/10/2025শেষবার password বদলানোর তারিখ
0password বদলাতে কমপক্ষে কত দিন অপেক্ষা (0 = কোনো বাধা নেই)
99999কত দিন পরে password-এর মেয়াদ শেষ (কার্যত কখনো না)
7মেয়াদ শেষের কত দিন আগে সতর্ক করবে
-1নিষ্ক্রিয়তার কারণে account বন্ধ হবে না
অন্য অক্ষর দেখলে

P মানে ব্যবহারযোগ্য password আছে (unlocked)। NP মানে কোনো password-ই সেট করা নেই। L মানে locked।

Account unlock করা

লক্ষ্য: ছুটি শেষ — fazlul-এর login আবার চালু করা।

bash
$ sudo usermod -U fazlul

এখানে সম্ভবত একটা error পাবে:

output — error
usermod: unlocking the user's password would result in a
         passwordless account.
You should set a password with usermod -p to unlock this
user's password.

কেন এই error: আমরা useradd দিয়ে user বানিয়েছিলাম কিন্তু কোনো password দিইনি। এখন unlock করলে account টা password ছাড়াই খুলে যেত — সেটা নিরাপত্তার দিক থেকে বিপজ্জনক। তাই Linux আগে password চাইছে।

সমাধান — আগে password দাও, তারপর unlock করো:

bash
# আগে একটা password সেট করো
$ sudo passwd fazlul

# তারপর unlock করো
$ sudo usermod -U fazlul

যাচাই করো:

bash
$ sudo passwd -S fazlul
output
fazlul P 02/10/2025 0 99999 7 -1
L থেকে P হয়ে গেছে — account এখন সচল, password সেট করা আছে।
এই error টাই আসলে শেখার জায়গা

Error টা বাধা নয়, বরং Linux-এর নিরাপত্তার নীতিটা দেখিয়ে দিচ্ছে — password ছাড়া কোনো account খোলা থাকবে না। Error message পড়লে সে নিজেই বলে দিচ্ছে কী করতে হবে। Linux-এ বেশিরভাগ error এমনই।

সব user-এর তালিকা দেখা

লক্ষ্য: system-এ কারা কারা আছে জানা।

bash
$ cat /etc/passwd
output — শেষের কয়েক লাইন
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
nabil:x:1000:1004::/home/nabil:/bin/sh
minhaz:x:1001:1001::/home/minhaz:/bin/sh
yasin:x:1002:1002::/home/yasin:/bin/sh
fazlul:x:1003:1003::/home/fazlul:/bin/sh

প্রতিটা লাইনের গঠন — : দিয়ে আলাদা করা সাতটা ঘর:

লাইনের গঠন
nabil : x : 1000 : 1004 :  : /home/nabil : /bin/sh
  │     │     │      │    │       │           │
  │     │     │      │    │       │           └─ login shell
  │     │     │      │    │       └───────────── home directory
  │     │     │      │    └───────────────────── পুরো নাম (খালি)
  │     │     │      └────────────────────────── primary GID
  │     │     └───────────────────────────────── UID
  │     └─────────────────────────────────────── password (shadow-এ আছে)
  └───────────────────────────────────────────── username
শুধু আসল মানুষদের দেখতে চাইলে

/etc/passwd-এ system-এর নিজের অনেক account-ও থাকে (daemon, www-data ইত্যাদি)। সাধারণ user-দের UID সাধারণত 1000 বা তার বেশি:

bash
$ awk -F: '$3 >= 1000 {print $1}' /etc/passwd

Lab 1-এর grep-এর মতোই — এখানে awk দিয়ে তৃতীয় ঘরটা (UID) দেখে বাছাই করা হচ্ছে।

নিজে করো — Challenge

  1. yasin-এর primary group বদলে poridhi-minions করো, তারপর getent দিয়ে দেখো group-এর সদস্য তালিকা থেকে তার নাম উধাও হয়ে গেল কিনা।
  2. interns নামে একটা নতুন group বানিয়ে minhaz-কে সেখানে supplementary হিসেবে যোগ করো — তার আগের group গুলো যেন ঠিক থাকে।
  3. System-এ কতজন সাধারণ user (UID ≥ 1000) আছে সেটা গুনে বের করো।
সমাধান দেখো
bash — solution
# ১ — primary group বদলানো
$ sudo usermod -g poridhi-minions yasin
$ getent group poridhi-minions
poridhi-minions:x:1004:minhaz,fazlul   # yasin আর তালিকায় নেই
$ id yasin
uid=1002(yasin) gid=1004(poridhi-minions) groups=1004(poridhi-minions)

# ২ — নতুন group + append
$ sudo groupadd interns
$ sudo usermod -aG interns minhaz
$ groups minhaz
minhaz : minhaz poridhi-minions interns

# ৩ — সাধারণ user গোনা
$ awk -F: '$3 >= 1000 {print $1}' /etc/passwd | wc -l

১ নম্বরটা Step 4-এর সেই confusion-টাই আবার প্রমাণ করছে — primary group হিসেবে থাকলে নাম /etc/group-এর সদস্য তালিকায় লেখা হয় না, কিন্তু user ঠিকই ঐ group-এ আছে।

Command গুলো এক নজরে

Commandকাজ
useradd <user>নতুন user বানায়
groupadd <group>নতুন group বানায়
usermod -g <group> <user>primary group বদলায়
usermod -aG <group> <user>supplementary group-এ যোগ করে
usermod -L <user>account lock করে
usermod -U <user>account unlock করে
passwd <user>password সেট বা বদলায়
passwd -S <user>account-এর অবস্থা দেখায় (L / P / NP)
id <user>UID, GID আর সব group দেখায়
groups <user>user কোন কোন group-এ আছে
getent group <group>group-এর supplementary সদস্যদের দেখায়
cat /etc/passwdসব user-এর তালিকা

userdel -r ঐ user-এর home directory আর তার ভেতরের সব file স্থায়ীভাবে মুছে দেয় — ফেরানোর উপায় নেই। নাম দুবার পড়ে তারপর Enter চাপো।

মূল কথা

Primary group একটাই, আর সেটা /etc/passwd-এ GID হিসেবে লেখা থাকে। Supplementary group যতগুলো খুশি, সেগুলো /etc/group-এ নাম হিসেবে লেখা থাকে। -g বদলায়, -aG যোগ করে — এই একটা অক্ষরের পার্থক্যই সবচেয়ে বেশি ভুল করায়।
