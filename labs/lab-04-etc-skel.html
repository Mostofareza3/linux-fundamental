Understanding /etc/skel/ in Linux

নতুন user বানালে তার home directory-তে .bashrc, .profile — এই file গুলো কোথা থেকে আসে? কেউ তো হাতে বানায় না। আসে /etc/skel/ থেকে। এটা একটা ছাঁচ — নতুন user-এর home directory ঠিক এই ছাঁচে ঢেলে বানানো হয়। এই lab-এ তুমি ছাঁচটা নিজের মতো বদলাবে, আর দেখবে পরের user সত্যিই সেটা পাচ্ছে কিনা।

এই lab শেষে যা পারবে

  • /etc/skel/ কী আর কখন কাজ করে, বলতে পারবে।
  • নতুন user বানিয়ে প্রমাণ করবে file গুলো সত্যিই copy হচ্ছে।
  • ছাঁচে নিজের file আর alias যোগ করবে — সব নতুন user সেটা পাবে।
  • ছাঁচ থেকে জিনিস সরিয়ে দিলে কী হয়, দেখবে।
  • home directory ছাড়া বানানো user-এর জন্য হাতে ছাঁচটা ঢালবে।
আগে যা জানা থাকলে সুবিধা

Lab 02 — User & Group Management। এখানে useradd -m বারবার লাগবে, তাই user বানানোর কাজটা আগে থেকে হাতে থাকলে সবচেয়ে ভালো।

practice machine-এ করো

এই lab-এ কয়েকজন test user বানানো হবে আর /etc/skel/ বদলানো হবে। কাজটা নিজের VM, WSL, container বা ফেলে দেওয়া যায় এমন VPS-এ করো। শেষে পরিষ্কার করার ধাপ দেওয়া আছে।

/etc/skel/ আসলে কী

skel এসেছে skeleton থেকে — কঙ্কাল। নামটাই বলে দিচ্ছে কাজটা কী: এটা নতুন user-এর home directory-র কঙ্কাল, মানে মূল কাঠামোটা।

নতুন user বানানোর সময় system এই folder-এর ভেতরের সবকিছু — লুকোনো file সহ — তুলে নিয়ে নতুন user-এর home directory-তে বসিয়ে দেয়। তাই প্রতিটা নতুন user একই রকম, আগে থেকে গোছানো একটা environment নিয়ে শুরু করে।

যা ঘটে
/etc/skel/                          /home/newuser/
├── .bashrc        ──┐              ├── .bashrc
├── .profile         ├─ copy ──→    ├── .profile
└── .bash_logout   ──┘              └── .bash_logout
                                    (ownership: newuser:newuser)
Fileকাজ
.bashrcbash shell চালু হলে যা যা চলবে — alias, prompt, environment
.profilelogin করার সময় একবার চলে — environment variable, PATH
.bash_logoutlogout করার সময় যা চলবে — যেমন screen পরিষ্কার করা
ছাঁচ বদলালে পুরোনো user-দের কিছু হয় না

এটা মনে রাখা সবচেয়ে জরুরি। /etc/skel/ শুধু user বানানোর মুহূর্তে একবার copy হয় — তারপর আর কোনো সম্পর্ক থাকে না। আজ ছাঁচে নতুন file যোগ করলে কালকের user সেটা পাবে, কিন্তু গতকালের user পাবে না।

এটা link নয়, copy। একবার ঢেলে দেওয়ার পর ছাঁচ আর তৈরি জিনিসটার মধ্যে আর কোনো যোগ নেই।

অনুশীলন

ছাঁচের ভেতরে কী আছে দেখা

লক্ষ্য: কাজ শুরুর আগে জানা — এখন ছাঁচে কী কী আছে।

bash
$ ls -la /etc/skel/
output
total 20
drwxr-xr-x  2 root root 4096 Jan 10 09:14 .
drwxr-xr-x 98 root root 4096 Mar 02 11:02 ..
-rw-r--r--  1 root root  220 Jan 10 09:14 .bash_logout
-rw-r--r--  1 root root 3771 Jan 10 09:14 .bashrc
-rw-r--r--  1 root root  807 Jan 10 09:14 .profile
তিনটে file-ই . দিয়ে শুরু — মানে লুকোনো file। তাই -a ছাড়া ls দিলে folder টা খালি মনে হবে।

ব্যাখ্যা:

Flagকী করে
-lলম্বা তালিকা — permission, মালিক, আকার, তারিখ
-aলুকোনো file-ও দেখায় (. দিয়ে শুরু হওয়া)
এখানে -a বাদ দিলে ভুল বুঝবে

ls /etc/skel/ দিলে বেশিরভাগ system-এ কিছুই দেখাবে না — কারণ সব file-ই লুকোনো। এই এক জায়গায় -a ভুলে গেলে মনে হবে ছাঁচটা খালি, অথচ তা নয়।

নতুন user বানিয়ে প্রমাণ করা

লক্ষ্য: ছাঁচের file গুলো সত্যিই copy হচ্ছে — নিজে চোখে দেখা।

bash
$ sudo useradd -m testuser

এবার তার home directory দেখো:

bash
$ ls -la /home/testuser/
output
total 20
drwxr-x--- 2 testuser testuser 4096 Mar 02 11:05 .
drwxr-xr-x 4 root     root     4096 Mar 02 11:05 ..
-rw-r--r-- 1 testuser testuser  220 Mar 02 11:05 .bash_logout
-rw-r--r-- 1 testuser testuser 3771 Mar 02 11:05 .bashrc
-rw-r--r-- 1 testuser testuser  807 Mar 02 11:05 .profile
হুবহু সেই তিনটে file। খেয়াল করো মালিক বদলে গেছে — ছাঁচে ছিল root, এখানে testuser।
-m না দিলে কিছুই হবে না

-m মানে "home directory বানাও"। এই flag ছাড়া useradd শুধু account-টা খোলে, কোনো folder বানায় না — আর folder না বানালে ছাঁচ ঢালারও প্রশ্ন নেই। Step 6-এ ঠিক এই পরিস্থিতিটা নিয়েই কাজ করব।

ছাঁচ আর ফলাফল পাশাপাশি মিলিয়ে দেখতে চাইলে:

bash
$ diff <(ls -A /etc/skel/) <(ls -A /home/testuser/)
output
(কোনো output নেই — মানে দুটো তালিকা হুবহু এক)
diff শুধু পার্থক্য দেখায়। চুপ থাকা মানে কোনো পার্থক্য নেই।

ছাঁচে নিজের file যোগ করা

লক্ষ্য: একটা welcome message বানানো, যা প্রত্যেক নতুন user পাবে।

bash
$ echo "Welcome to this system, enjoy your stay!" | sudo tee /etc/skel/welcome.txt
output
Welcome to this system, enjoy your stay!
tee একই সাথে file-এ লেখে আর screen-এও দেখায় — তাই লেখাটা দুবার দেখছ মনে হতে পারে।
sudo echo "..." > file কেন কাজ করে না

স্বাভাবিক মনে হয় sudo echo "..." > /etc/skel/welcome.txt লিখলেই হবে। কিন্তু হয় না — Permission denied আসে।

কারণ > চিহ্নটা sudo-র কাজ নয়, সেটা shell-এর কাজ। আর shell টা চলছে তোমার সাধারণ user হিসেবে। তাই sudo শুধু echo-কে root বানায়, কিন্তু file-এ লেখার কাজটা করে সেই সাধারণ shell — যার অনুমতি নেই।

tee এই সমস্যাটা এড়ায়, কারণ লেখার কাজটা tee নিজেই করে — আর tee-কে sudo দিয়ে চালানো যায়।

এবার নতুন user বানিয়ে দেখো:

bash
$ sudo useradd -m testuser2
$ ls -la /home/testuser2/
output
-rw-r--r-- 1 testuser2 testuser2  220 Mar 02 11:12 .bash_logout
-rw-r--r-- 1 testuser2 testuser2 3771 Mar 02 11:12 .bashrc
-rw-r--r-- 1 testuser2 testuser2  807 Mar 02 11:12 .profile
-rw-r--r-- 1 testuser2 testuser2   41 Mar 02 11:12 welcome.txt
welcome.txt চলে এসেছে।

এখন পুরোনো user-কে দেখো — সেখানে কিন্তু আসেনি:

bash
$ ls /home/testuser/welcome.txt
output
ls: cannot access '/home/testuser/welcome.txt': No such file or directory
এটাই সেই কথাটার প্রমাণ — ছাঁচ শুধু ভবিষ্যতের user-দের জন্য। testuser আগেই বানানো হয়ে গেছে, তাই সে বাদ পড়ল।

ছাঁচের .bashrc বদলানো — alias আর welcome message

লক্ষ্য: প্রত্যেক নতুন user যেন কিছু তৈরি alias আর একটা অভ্যর্থনা পায়।

bash
$ sudo cp /etc/skel/.bashrc /etc/skel/.bashrc.bak
$ sudo vim /etc/skel/.bashrc

প্রথম লাইনটা একটা backup — বদলানোর আগে আসল file-এর একটা copy রেখে দেওয়া। কিছু ভুল হলে ফিরে আসা যাবে।

File-এর একদম শেষে এই অংশটা যোগ করো:

/etc/skel/.bashrc
# Custom aliases
alias myinfo='echo "Current user: $(whoami)"'
alias diskspace='df -h /'

# Welcome message displayed at login
echo "Welcome to your Linux environment!"

Save করে বেরিয়ে এসো। vim হলে Esc → :wq → Enter; nano হলে Ctrl+O → Enter → Ctrl+X।

alias-এ single quote কেন

alias myinfo='... $(whoami) ...' — এখানে single quote (') ব্যবহার করা হয়েছে ইচ্ছে করে। Single quote-এর ভেতরে $(whoami) এখনই চলে না, লেখা হিসেবেই জমা থাকে — আর চলে প্রতিবার যখন তুমি myinfo লেখো।

Double quote (") দিলে $(whoami) alias বানানোর মুহূর্তেই চলে যেত, আর সেই একটা উত্তরই চিরকাল আটকে থাকত।

নতুন user বানাও — এবার shell-টা স্পষ্ট করে বলে দাও:

bash
$ sudo useradd -m -s /bin/bash testuser3
$ sudo passwd testuser3
-s /bin/bash বাদ দিলে কিছুই দেখবে না

কিছু system-এ নতুন user-এর default shell থাকে /bin/sh। আর /bin/sh .bashrc পড়েই না — ওটা bash-এর নিজস্ব file। তখন alias-ও আসবে না, welcome message-ও না, আর তুমি ভাববে ছাঁচ কাজ করছে না।

তাই -s /bin/bash দিয়ে shell-টা স্পষ্ট করে বলে দেওয়াই নিরাপদ।

ঐ user হয়ে ঢোকো:

bash
$ su - testuser3
output
Password:
Welcome to your Linux environment!
testuser3@labserver:~$
Welcome message এসেছে — মানে ছাঁচের .bashrc সত্যিই copy হয়েছে আর চলছে।

alias দুটো পরীক্ষা করো:

bash — testuser3 হিসেবে
$ myinfo
$ diskspace
output
$ myinfo
Current user: testuser3

$ diskspace
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        49G   12G   35G  26% /
myinfo নিজে থেকেই বলে দিচ্ছে কে চালাচ্ছে — কারণ single quote-এর জন্য whoami প্রতিবার নতুন করে চলছে।
su - testuser3 দিলে SSH agent-এর error আসছে?

Container বা কিছু setup-এ su - করার সময় এরকম কিছু লাইন দেখা যেতে পারে:

output
Could not open a connection to your authentication agent.

এটা ছাঁচের সাথে সম্পর্কহীন — environment-এর ব্যাপার, নিরাপদে অগ্রাহ্য করা যায়। আসল কথা হলো এর পরেও welcome message-টা এসেছে কিনা। এলেই কাজ হয়েছে।

চাইলে ছাঁচেই একটা তৈরি .ssh folder রেখে দিতে পারো, তাহলে প্রত্যেক নতুন user সেটা ঠিক permission সহ পাবে — Challenge-এ এটা আছে।

কাজ শেষে নিজের account-এ ফিরে এসো:

bash
$ exit

ছাঁচ থেকে জিনিস সরিয়ে দেওয়া

লক্ষ্য: উল্টো দিকটাও পরীক্ষা করা — সরালে সত্যিই আর যায় না তো?

bash
$ sudo rm /etc/skel/welcome.txt

এখন নতুন একজন user বানাও:

bash
$ sudo useradd -m testuser4
$ ls -la /home/testuser4/
output
-rw-r--r-- 1 testuser4 testuser4  220 Mar 02 11:30 .bash_logout
-rw-r--r-- 1 testuser4 testuser4 3922 Mar 02 11:30 .bashrc
-rw-r--r-- 1 testuser4 testuser4  807 Mar 02 11:30 .profile
এবার welcome.txt নেই। অথচ .bashrc-র আকার 3922 — আগের 3771-এর চেয়ে বড়, কারণ Step 4-এ যোগ করা লাইনগুলো এখনো ছাঁচে আছে।

তিনজন user পাশাপাশি রাখলে পুরো ব্যাপারটা এক নজরে বোঝা যায়:

কে কী পেল
                  welcome.txt   বদলানো .bashrc
testuser             ✗                ✗        ← ছাঁচ বদলানোর আগে বানানো
testuser2            ✓                ✗        ← welcome যোগ করার পরে
testuser3            ✓                ✓        ← .bashrc বদলানোর পরে
testuser4            ✗                ✓        ← welcome সরানোর পরে
প্রত্যেক user ছাঁচের সেই মুহূর্তের চেহারাটা নিয়ে জন্মেছে — তারপর আর বদলায়নি।

home directory ছাড়া বানানো user — হাতে ছাঁচ ঢালা

লক্ষ্য: -m ভুলে গেলে কী হয়, আর সেটা পরে কীভাবে ঠিক করতে হয়।

এবার ইচ্ছে করেই -m ছাড়া একজন user বানাও:

bash
$ sudo useradd testuser5
$ ls -la /home/testuser5/
output
ls: cannot access '/home/testuser5/': No such file or directory
Account আছে (id testuser5 দিয়ে দেখো), কিন্তু থাকার জায়গা নেই।

হাতে home directory বানাও:

bash
$ sudo mkdir /home/testuser5
$ ls -la /home/testuser5/
output
total 8
drwxr-xr-x 2 root root 4096 Mar 02 11:38 .
drwxr-xr-x 7 root root 4096 Mar 02 11:38 ..
Folder খালি, আর মালিক root — user নিজে এখানে কিছু লিখতেও পারবে না। দুটোই ঠিক করতে হবে।

ছাঁচটা হাতে ঢেলে দাও:

bash
$ sudo cp -r /etc/skel/. /home/testuser5/
$ sudo chown -R testuser5:testuser5 /home/testuser5/
শেষের ঐ বিন্দুটা (/etc/skel/.) খুব জরুরি

তিনটে লেখার তিন রকম মানে:

যা লিখলেযা হবে
cp -r /etc/skel /home/testuser5/ভেতরে skel নামে একটা folder বসবে — যা চাইনি
cp -r /etc/skel/* /home/testuser5/শুধু সাধারণ file যাবে, লুকোনো file গুলো বাদ পড়বে — অর্থাৎ .bashrc-ই যাবে না!
cp -r /etc/skel/. /home/testuser5/ভেতরের সবকিছু, লুকোনো file সহ — এটাই চাই

মাঝেরটাই সবচেয়ে বিপজ্জনক, কারণ command টা চলে যায় কোনো error ছাড়াই — শুধু আসল file গুলোই বাদ পড়ে থাকে।

যাচাই করো:

bash

ব্যাখ্যা — দুটো command দুটো আলাদা কাজ করছে:

Commandকাজ
cp -rfolder সহ ভেতরের সবকিছু copy করে (-r = recursive)
chown -R user:groupমালিকানা বদলায়, -R দিয়ে ভেতরের সব file-এও
chown ভুলে গেলে যা হয়

File গুলো root-এর মালিকানায় থেকে যাবে। তখন user নিজের .bashrc সম্পাদনা করতে পারবে না, কিছু program নিজের setting লিখতে গিয়ে আটকে যাবে — অথচ ls দেখে সব ঠিকঠাক মনে হবে। এই ভুলটা ধরা কঠিন, তাই cp-র পরেই chown করার অভ্যাস করো।

আসলে একটাই command-এ হয়ে যেত
bash
$ sudo mkhomedir_helper testuser5

Debian/Ubuntu-তে এই একটা command নিজেই folder বানায়, ছাঁচ ঢালে আর মালিকানা ঠিক করে দেয়। তবু হাতে করাটা একবার শিখে রাখা ভালো — তাহলে ভেতরে ঠিক কী ঘটছে সেটা জানা থাকে, আর যেসব system-এ এই helper নেই সেখানেও আটকাবে না।

ছাঁচের ঠিকানা বদলানোও যায়

Default ঠিকানাটা লেখা থাকে /etc/default/useradd file-এ:

bash
$ grep SKEL /etc/default/useradd
output
SKEL=/etc/skel

একবারের জন্য অন্য ছাঁচ ব্যবহার করতে চাইলে useradd -k /path/to/other-skel -m username — যেমন developer-দের জন্য এক ছাঁচ, সাধারণ user-দের জন্য আরেকটা।

নিজে করো — Challenge

  1. ছাঁচে একটা projects নামের খালি folder বানাও, তারপর নতুন user বানিয়ে দেখো সেটা এসেছে কিনা।
  2. ছাঁচে .ssh folder বানাও 700 permission দিয়ে, ভেতরে খালি authorized_keys file 600 permission দিয়ে। নতুন user বানিয়ে permission গুলো মিলিয়ে দেখো।
  3. /etc/skel-dev/ নামে আলাদা একটা ছাঁচ বানাও, তাতে অন্যরকম .bashrc রাখো, তারপর -k দিয়ে সেই ছাঁচ থেকে একজন user বানাও।
সমাধান দেখো
bash — solution
# ১ — ছাঁচে folder
$ sudo mkdir /etc/skel/projects
$ sudo useradd -m ch1user
$ ls -la /home/ch1user/
drwxr-xr-x 2 ch1user ch1user 4096 Mar 02 11:52 projects

File-ই হোক বা folder — ছাঁচের ভেতরের সবকিছুই যায়। মালিকানাও নতুন user-এর নামে বসে যায়।

bash — solution
# ২ — .ssh ঠিক permission সহ
$ sudo mkdir -p /etc/skel/.ssh
$ sudo touch /etc/skel/.ssh/authorized_keys
$ sudo chmod 700 /etc/skel/.ssh
$ sudo chmod 600 /etc/skel/.ssh/authorized_keys

$ sudo useradd -m ch2user
$ sudo ls -la /home/ch2user/.ssh/
drwx------ 2 ch2user ch2user 4096 Mar 02 11:55 .
-rw------- 1 ch2user ch2user    0 Mar 02 11:55 authorized_keys

Permission গুলোও ছাঁচ থেকেই এসেছে — cp সেগুলো ধরে রাখে। এটা .ssh-র ক্ষেত্রে দরকারি, কারণ permission একটু ঢিলে হলে SSH নিজেই key টা মানতে অস্বীকার করে।

bash — solution
# ৩ — আলাদা ছাঁচ
$ sudo cp -r /etc/skel /etc/skel-dev
$ echo 'alias gs="git status"' | sudo tee -a /etc/skel-dev/.bashrc

$ sudo useradd -k /etc/skel-dev -m -s /bin/bash devuser
$ sudo grep "git status" /home/devuser/.bashrc
alias gs="git status"

$ sudo useradd -m -s /bin/bash normaluser
$ sudo grep "git status" /home/normaluser/.bashrc
(কিছুই নেই — সে default ছাঁচ থেকে এসেছে)

tee -a-তে -a মানে append — file-এর শেষে যোগ করো, আগেরটা মুছে দিও না। -a ভুলে গেলে পুরো .bashrc মুছে গিয়ে শুধু ঐ এক লাইনটাই থেকে যাবে।

Command গুলো এক নজরে

Commandকাজ
ls -la /etc/skel/ছাঁচের ভেতরে কী আছে দেখায় (লুকোনো file সহ)
useradd -m <user>home directory সহ user বানায়, ছাঁচ ঢালে

আটকে গেলে

সমস্যাকী হয়েছে / কী করবে
ls /etc/skel/ খালি দেখাচ্ছেসব file লুকোনো। -a যোগ করো — ls -la /etc/skel/।
নতুন user welcome message পাচ্ছে নাতার shell সম্ভবত /bin/sh। getent passwd <user> দিয়ে দেখো; usermod -s /bin/bash <user> দিয়ে বদলাও।
পুরোনো user নতুন file পাচ্ছে নাএটা ভুল নয়, এটাই নিয়ম। ছাঁচ শুধু নতুন user-দের জন্য। পুরোনোদের দিতে হলে হাতে cp করে chown করতে হবে।
sudo echo > /etc/skel/... এ Permission denied> চালায় তোমার নিজের shell, root নয়। | sudo tee <file> ব্যবহার করো।
হাতে copy করার পরও .bashrc নেই/etc/skel/* লিখেছ সম্ভবত — * লুকোনো file ধরে না। /etc/skel/. লেখো।
User নিজের file edit করতে পারছে নাchown বাদ পড়েছে। sudo chown -R <user>:<user> /home/<user>/ চালাও।
useradd: user already existsআগের চেষ্টায় বানানো হয়ে গেছে। sudo userdel -r <user> দিয়ে মুছে আবার শুরু করো।

/etc/skel/-এর ভেতরে শুধু নিজের যোগ করা জিনিসগুলোই মুছবে। আসল .bashrc, .profile, .bash_logout মুছে ফেললে এরপর বানানো প্রতিটা user একদম খালি, setting-হীন home directory নিয়ে জন্মাবে। Step 4-এ যে backup রেখেছিলে, সেটা এখানেই কাজে লাগল।

আর userdel -r home directory সহ সব মুছে দেয় — ফেরানোর উপায় নেই।

মূল কথা

/etc/skel/ হলো নতুন user-এর home directory-র ছাঁচ। যা কিছু ওখানে রাখবে — file, folder, alias, permission — প্রত্যেক নতুন user সেটা নিয়েই জন্মাবে। একবার ছাঁচটা ঠিক করে সাজিয়ে রাখলে আর কখনো হাতে করে প্রত্যেকের environment গোছাতে হয় না।

তবে মনে রেখো — ছাঁচ কাজ করে শুধু জন্মের মুহূর্তে। পুরোনো user-দের কিছু দিতে হলে সেটা হাতেই করতে হবে, বা /etc/bash.bashrc-র মতো system-wide file ব্যবহার করতে হবে।
