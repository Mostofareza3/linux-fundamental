Linux User Modification

Account বানানো সহজ অংশ। আসল কাজ শুরু হয় তার পরে — কারো নাম বদলায়, কেউ অন্য টিমে যায়, কারো shell বদলাতে হয়, কারো account-এর একটা মেয়াদ বেঁধে দিতে হয়। এই সবকিছুর জন্য একটাই command — usermod। এই lab-এ তুমি একটা account-কে ধাপে ধাপে ভেঙেচুরে নতুন করে গড়বে, আর প্রতিবার দেখবে system-এর ঠিক কোন file-টা বদলাচ্ছে।

এই lab শেষে যা পারবে

  • Username, shell, home directory, UID — সব বদলাতে পারবে।
  • বুঝবে কোন পরিবর্তনে system নিজে থেকে কী কী ঠিক করে দেয়, আর কী দেয় না।
  • chage দিয়ে password-এর মেয়াদ আর account-এর মেয়াদ আলাদা করে বুঝবে।
  • Account lock করে /etc/shadow-তে ঠিক কী ঘটে সেটা দেখবে।
  • একটা command-এই পুরো সাজানো account বানাবে।
আগে যা জানা থাকলে সুবিধা

Lab 02 — User & Group Management। ওখানে user আর group বানানো শিখেছ; এই lab পুরোটাই বানানো জিনিস বদলানো নিয়ে। Primary আর supplementary group-এর পার্থক্যটা ওখান থেকে মনে করে নিলে এখানে সুবিধা হবে।

practice machine-এ করো

এই lab-এ UID বদলানো, home directory সরানো, account-এ মেয়াদ বসানো — সবই আছে। Production server-এ এসব করলে চলমান service ভেঙে যেতে পারে। কাজটা নিজের VM, WSL, container বা ফেলে দেওয়া যায় এমন VPS-এ করো। শেষে পরিষ্কার করার ধাপ দেওয়া আছে।

User-এর তথ্য আসলে কোথায় থাকে

এই lab-এর প্রতিটা command আসলে তিনটে text file-এর কোনো একটা বদলাচ্ছে। এই তিনটে চিনে রাখলে বাকি সব ধাপ নিজে থেকেই পরিষ্কার হয়ে যাবে:

Fileকী থাকে
/etc/passwdusername, UID, GID, comment, home directory, shell
/etc/shadowpassword-এর hash আর password-সংক্রান্ত সব মেয়াদ
/etc/groupকোন group-এ কারা আছে
/etc/passwd-এর একটা লাইন
testuser:x:1001:1001:Test User Account:/home/testuser:/bin/bash
    │    │  │    │          │                 │            │
    │    │  │    │          │                 │            └─ shell
    │    │  │    │          │                 └────────────── home directory
    │    │  │    │          └──────────────────────────────── comment (GECOS)
    │    │  │    └─────────────────────────────────────────── primary group-এর GID
    │    │  └──────────────────────────────────────────────── UID
    │    └─────────────────────────────────────────────────── password এখানে নেই (x = shadow-এ আছে)
    └──────────────────────────────────────────────────────── username
ঐ 'x' টা password নয়

অনেক পুরোনো Unix-এ ঐ ঘরেই password-এর hash থাকত। কিন্তু /etc/passwd file-টা সবাই পড়তে পারে — তাই সেটা ছিল বিপজ্জনক। এখন hash সরিয়ে রাখা হয় /etc/shadow-তে, যেটা শুধু root পড়তে পারে। x মানে শুধু "password অন্য জায়গায় খোঁজো"।

এজন্যই এই lab-এ grep testuser /etc/passwd চলে sudo ছাড়া, কিন্তু chage -l বা passwd -S-এ sudo লাগে।

যে পথটা আমরা হাঁটব

একটাই account, ধাপে ধাপে বদলাতে বদলাতে অন্যরকম হয়ে যাবে:

যা করতে যাচ্ছি
testuser  বানানো
   │
   ├─ testgroup-এ যোগ করা          (usermod -aG)
   ├─ shell → /bin/bash             (usermod -s)
   ├─ নাম → newuser                 (usermod -l)
   ├─ home → /home/newuser          (usermod -d -m)
   ├─ মেয়াদ → 2025-12-31            (usermod -e)
   ├─ UID → 1100                    (usermod -u)
   ├─ lock → unlock                 (usermod -L / -U)
   └─ comment → "Test User Account" (usermod -c)

customuser  ← এই সবকিছু একটা command-এ  (useradd)

অনুশীলন

Part 1 — User আর group বানানো

যা বদলাবো, আগে সেটা বানিয়ে নাও

লক্ষ্য: একটা user আর একটা group — বাকি পুরো lab এদের নিয়েই।

bash
$ sudo useradd -m testuser
$ sudo groupadd testgroup

যাচাই করো — দুটো আলাদা file-এ দুটো লাইন বসেছে:

bash
$ grep testuser /etc/passwd
$ grep testgroup /etc/group
output
$ grep testuser /etc/passwd
testuser:x:1001:1001::/home/testuser:/bin/sh

$ grep testgroup /etc/group
testgroup:x:1002:
দুটো জিনিস খেয়াল করো — shell হলো /bin/sh (Step 3-এ বদলাবো), আর comment-এর ঘরটা খালি (1001:: — দুটো colon পাশাপাশি)। testgroup-এর শেষে কিছু নেই, মানে এখনো কোনো সদস্য নেই।
grep দিয়ে দেখার চেয়ে ভালো উপায়
bash
$ getent passwd testuser
$ getent group testgroup

grep শুধু file-টা পড়ে। getent পড়ে system-কে জিজ্ঞেস করে — তাই user যদি LDAP বা Active Directory-র মতো কোনো বাইরের জায়গা থেকে আসে, getent তাকেও খুঁজে পায়, grep পায় না। অভ্যাসটা getent-এর করাই ভালো।

আর grep testuser দিলে যে কোনো লাইনে ঐ শব্দটা থাকলেই সেটা দেখাবে — যেমন testuser2-ও ধরা পড়বে। getent হুবহু মেলে।

Group-এ যোগ করা — আর সেই ভয়ংকর -a

লক্ষ্য: testuser-কে testgroup-এ বসানো, পুরোনো group না হারিয়ে।

bash
$ sudo usermod -a -G testgroup testuser
$ groups testuser
output
testuser : testuser testgroup
প্রথমটা তার primary group (নিজের নামে), দ্বিতীয়টা নতুন supplementary group।
-a বাদ দিলে আগের সব group মুছে যায়

-G মানে "supplementary group-এর তালিকাটা এই হবে" — অর্থাৎ পুরো তালিকা বদলে দেওয়া। -a (append) যোগ করলে তবেই সেটা হয় "তালিকায় আরেকটা যোগ করো"।

পার্থক্যটা
user আগে ছিল:  developers, docs, sudo

usermod -aG testgroup user  →  developers, docs, sudo, testgroup  ✓
usermod -G  testgroup user  →  testgroup                          ✗ বাকি সব গেল

বাস্তবে এই এক অক্ষরের ভুলে মানুষ নিজের sudo access হারিয়ে ফেলে — আর তখন সেটা ফেরত আনতেও sudo লাগত। তাই -G লিখলেই সাথে -a লেখার অভ্যাস করো।

-aG আর -a -G — দুটো একই জিনিস, শুধু লেখার ধরন আলাদা।

-g (ছোট হাতের) আবার আলাদা

-g দিয়ে primary group বদলায়, -G দিয়ে supplementary। ছোট-বড় হাতের এই একটা অক্ষরের তফাতেই কাজ সম্পূর্ণ আলাদা। Part 5-এ একই command-এ দুটোই একসাথে ব্যবহার করব।

Part 2 — Attribute বদলানো

Shell বদলানো

লক্ষ্য: /bin/sh থেকে /bin/bash।

bash
$ sudo usermod -s /bin/bash testuser
$ getent passwd testuser
output
testuser:x:1001:1001::/home/testuser:/bin/bash
লাইনের একদম শেষের ঘরটা বদলে গেছে — আর কিছু না।
Lab 4-এর সাথে মিলিয়ে নাও

Lab 04-এ দেখেছিলে /bin/sh user-এর .bashrc পড়ে না — তাই ছাঁচে রাখা alias আর welcome message কিছুই আসত না। এই command-টাই সেই সমস্যার সমাধান, পরে থেকে।

যেসব shell নেই, সেগুলো বসানো যাবে না

System যে shell গুলো চেনে তার তালিকা থাকে /etc/shells-এ:

bash
$ cat /etc/shells

ভুল path দিলে usermod সাধারণত একটা সতর্কবার্তা দেয়, কিন্তু কাজটা করেও ফেলে — আর তখন ঐ user আর login করতে পারে না। তাই bash আছে কিনা which bash দিয়ে আগে দেখে নাও।

ইচ্ছে করে login বন্ধ করার একটা কৌশল

Service account-দের (যেমন www-data) shell হিসেবে ইচ্ছে করেই /usr/sbin/nologin বসানো হয় — তাদের কাজ আছে, কিন্তু কারো login করার দরকার নেই:

bash
$ getent passwd www-data
output
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin

এটা lock করা নয় — Step 8-এর -L-এর সাথে গুলিয়ে ফেলো না। এখানে account সচল, শুধু shell-টা এমন যে login করলেই বের করে দেয়।

Username বদলানো — আর যা যা বদলায় না

লক্ষ্য: testuser → newuser, আর তার পিছনে পড়ে থাকা জিনিসগুলো খুঁজে বের করা।

bash
$ sudo usermod -l newuser testuser

ক্রমটা খেয়াল করো — আগে নতুন নাম, পরে পুরোনো নাম। উল্টো লিখলে user 'newuser' does not exist বলবে।

bash
$ getent passwd newuser
output
newuser:x:1001:1001::/home/testuser:/bin/bash
নাম বদলেছে, কিন্তু home directory এখনো /home/testuser! এটাই পরের step-এর কাজ।
-l শুধু নামটাই বদলায়, আর কিচ্ছু না

নাম বদলানোর পরেও যা যা আগের মতোই থেকে যায়:

যা থেকে যায়ঠিক করতে
Home directory-র নামusermod -d /home/newuser -m newuser (Step 5)
Primary group-এর নাম (testuser)groupmod -n newuser testuser
Mail spool-এর file-এর নামহাতে mv
Cron job, sudoers-এ লেখা পুরোনো নামহাতে খুঁজে বদলাতে হবে

এজন্যই বাস্তবে username বদলানো এড়িয়ে চলা হয় — নতুন account বানিয়ে file গুলো সরিয়ে নেওয়া অনেক সময় নিরাপদ।

ঐ user login করা অবস্থায় নাম বদলানো যায় না

চেষ্টা করলে বলবে:

output
usermod: user testuser is currently used by process 2841

কে কী চালাচ্ছে দেখতে sudo pkill -u testuser দিয়ে তার সব process বন্ধ করে নাও, নাহলে who দিয়ে দেখো সে কোথায় login করে আছে।

Home directory বদলানো

লক্ষ্য: folder-টার নামও বদলানো, আর ভেতরের file গুলো সাথে নিয়ে যাওয়া।

bash
$ sudo usermod -d /home/newuser -m newuser
$ getent passwd newuser
output
newuser:x:1001:1001::/home/newuser:/bin/bash

Folder-টা সত্যিই সরেছে কিনা দেখো:

bash
$ ls -la /home/newuser
$ ls /home/testuser
output
$ ls -la /home/newuser
drwxr-x--- 2 newuser newuser 4096 Mar 02 12:10 .
-rw-r--r-- 1 newuser newuser  220 Mar 02 12:04 .bash_logout
-rw-r--r-- 1 newuser newuser 3771 Mar 02 12:04 .bashrc
-rw-r--r-- 1 newuser newuser  807 Mar 02 12:04 .profile

$ ls /home/testuser
ls: cannot access '/home/testuser': No such file or directory
পুরোনো folder-টা আর নেই — সরে গেছে, copy হয়নি। File গুলো Lab 04-এর /etc/skel/ থেকেই এসেছিল।
-m ছাড়া -d দিলে user তার সব file হারায়

এই দুটো flag আলাদা কাজ করে:

Flagকী করে
-d/etc/passwd-এ শুধু ঠিকানাটা বদলায়
-mপুরোনো folder-টা সত্যিই নতুন জায়গায় সরিয়ে নেয়

শুধু -d দিলে /etc/passwd বলবে home হলো /home/newuser — কিন্তু সেই folder-টাই নেই। তখন login করলে user গিয়ে পড়বে /-তে, আর তার সব file পড়ে থাকবে পুরোনো folder-এ, অনাথ হয়ে।

-m নিজে থেকেই মালিকানা ঠিক করে দেয়

Lab 04-এ হাতে cp করার পর chown -R করতে হয়েছিল। এখানে সেটা লাগেনি — usermod -m সরানোর সাথে সাথে ভেতরের সব file-এর মালিকানাও ঠিক করে দেয়। উপরের output-এ newuser newuser দেখেই সেটা বোঝা যাচ্ছে।

Password দেওয়া

লক্ষ্য: account-টা সত্যিই ব্যবহারযোগ্য করা — পরের step গুলোর জন্য এটা দরকার।

bash
$ sudo passwd newuser
output
New password:
Retype new password:
passwd: password updated successfully
টাইপ করার সময় screen-এ কিছুই দেখা যাবে না — কোনো তারা চিহ্নও না। এটা স্বাভাবিক।
এটা কেন এখনই দরকার

Password ছাড়া account-এ Step 8-এর lock/unlock দেখে বোঝার কিছু থাকে না — passwd -S তখন L-ও না, P-ও না, দেখায় NP (no password)। আর Step 9-এর password-এর মেয়াদও তখন অর্থহীন, কারণ মেয়াদ দেওয়ার মতো কোনো password-ই নেই।

Account-এর মেয়াদ আর UID

লক্ষ্য: একটা তারিখ বেঁধে দেওয়া, আর UID বদলানোর ফাঁদটা চেনা।

প্রথমে মেয়াদ:

bash
$ sudo usermod -e 2025-12-31 newuser
$ sudo chage -l newuser
output
Last password change                    : Mar 02, 2026
Password expires                        : never
Password inactive                       : never
Account expires                         : Dec 31, 2025
Minimum number of days between password change : 0
Maximum number of days between password change : 99999
Number of days of warning before password expires : 7
তারিখটা লিখতে হয় YYYY-MM-DD ছাঁচে। খেয়াল করো — এই তারিখটা আজকের আগে, অর্থাৎ account-টা এইমাত্র মেয়াদোত্তীর্ণ হয়ে গেল!
চলে যাওয়া তারিখ দিলে account সাথে সাথে বন্ধ

usermod -e ভবিষ্যতের তারিখ চায়। অতীতের তারিখ দিলে user পরের বার login করতে গেলেই দেখবে:

output
Your account has expired; please contact your system administrator

# ভবিষ্যতের তারিখ
$ sudo usermod -e 2027-12-31 newuser

# মেয়াদ তুলে নাও

$ sudo usermod -u 1100 newuser

UID বদলালে পুরোনো file গুলো অনাথ হয়ে যায়

File-এর ভেতরে মালিকের নাম লেখা থাকে না, লেখা থাকে UID নম্বর। তাই UID বদলানো মানে ঐ user-এর পুরোনো সব file-এর মালিক এখন এমন একটা নম্বর, যেটা আর কারো নয়।

usermod -u home directory-র ভেতরটা নিজে থেকে ঠিক করে দেয়, কিন্তু বাইরের কোনো file নয় — যেমন /var/www বা /opt-এ থাকা file:

bash
# পুরোনো UID-র অনাথ file খুঁজে বের করো
$ sudo find / -uid 1001 -not -path "/proc/*" 2>/dev/null

# পেলে মালিকানা ঠিক করো
$ sudo find / -uid 1001 -not -path "/proc/*" -exec chown newuser {} \;

এজন্যই চালু system-এ UID বদলানো এড়িয়ে চলা হয়। একান্ত দরকার হলে আগে ঐ user-এর সব process বন্ধ করো, তারপর বদলাও, তারপর find দিয়ে খুঁজে সব ঠিক করো।

Part 3 — Lock, মেয়াদ আর comment

Lock করলে ভেতরে ঠিক কী ঘটে

লক্ষ্য: /etc/shadow-তে পরিবর্তনটা নিজে চোখে দেখা।

Lock করার আগে shadow file-এর লাইনটা দেখে নাও:

bash
$ sudo grep newuser /etc/shadow
output
newuser:$y$j9T$Kd8v...:20515:0:99999:7:::

এবার lock করো:

bash
$ sudo usermod -L newuser
$ sudo grep newuser /etc/shadow
$ sudo passwd -S newuser
output
$ sudo grep newuser /etc/shadow
newuser:!$y$j9T$Kd8v...:20515:0:99999:7:::

$ sudo passwd -S newuser
newuser L 03/02/2026 0 99999 7 -1
পুরো কৌশলটা ঐ একটা ! চিহ্ন — hash-এর সামনে বসে গেছে।
একটা বিস্ময়বোধক চিহ্নেই পুরো কাজ

Login করার সময় system তোমার দেওয়া password-টা hash করে, তারপর shadow file-এর hash-এর সাথে মেলায়। এখন সামনে ! বসে যাওয়ায় সেটা আর কোনো বৈধ hash-ই নয় — তাই কোনো password দিয়েই আর মেলানো সম্ভব নয়।

আসল hash-টা কিন্তু !-এর পিছনে অক্ষত আছে। তাই usermod -U দিয়ে শুধু ! চিহ্নটা তুলে নিলেই পুরোনো password আবার আগের মতো কাজ করে — নতুন করে password দিতে হয় না।

এবার unlock করো:

bash
$ sudo usermod -U newuser
$ sudo passwd -S newuser
output
newuser P 03/02/2026 0 99999 7 -1
L থেকে P — আবার সচল।
passwd -S-এর অক্ষরমানে
PPassword আছে, account সচল
LLocked — hash-এর সামনে ! বসানো
NPকোনো password নেই (Step 6 না করলে এটাই দেখতে)
Lock করা মানে পুরোপুরি বন্ধ নয়

-L শুধু password দিয়ে login বন্ধ করে। কিন্তু user যদি SSH key দিয়ে ঢোকে, সে কিন্তু এখনো ঢুকতে পারবে — কারণ সেখানে password-এর দরকারই হয় না।

সত্যিকারের পুরো বন্ধ করতে তিনটে একসাথে লাগে:

bash
$ sudo usermod -L newuser                      # password বন্ধ
$ sudo usermod -s /usr/sbin/nologin newuser     # shell বন্ধ
$ sudo usermod -e 1 newuser                     # account মেয়াদোত্তীর্ণ

কেউ কোম্পানি ছেড়ে গেলে বাস্তবে এই তিনটেই করা হয়, account মুছে ফেলার আগে।

GECOS — নামটা এলো কোথা থেকে

এই ঘরটার পোশাকি নাম GECOS field। নামটা ১৯৭০-এর দশকের একটা operating system-এর (General Electric Comprehensive Operating System) নাম থেকে এসেছে — সেই system-এ printer-এ কাজ পাঠানোর জন্য কিছু তথ্য এখানে রাখতে হতো।

সেই system কবেই হারিয়ে গেছে, কিন্তু নামটা রয়ে গেছে। এখন এখানে থাকে user-এর পুরো নাম, বিভাগ, ফোন নম্বর — comma দিয়ে আলাদা করে:

bash
$ sudo usermod -c "Nabil Ahmed,Engineering,+8801700000000" newuser

finger-এর মতো পুরোনো command গুলো এই comma গুলো বুঝে সাজিয়ে দেখাত।

এখানে colon লেখা যাবে না

/etc/passwd-এ ঘর আলাদা করা হয় colon (:) দিয়ে। Comment-এ একটা colon ঢুকিয়ে দিলে file-এর ঐ লাইনে ঘরের সংখ্যা বেড়ে যাবে, আর লাইনটা নষ্ট হয়ে যাবে। usermod সাধারণত আটকে দেয়, কিন্তু হাতে file edit করলে সে সুরক্ষাটুকুও থাকে না।

Part 4 — একটা command-এ পুরোটা

সব attribute একসাথে দিয়ে user বানানো

লক্ষ্য: Step ১ থেকে ১০ পর্যন্ত যা করলে, সেটা একটা লাইনে।

$ sudo useradd -m -s /bin/bash blockeduser
$ sudo passwd blockeduser

$ sudo usermod -L blockeduser
$ sudo usermod -s /usr/sbin/nologin blockeduser
$ sudo usermod -e 1 blockeduser

$ sudo passwd -S blockeduser
blockeduser L 03/02/2026 0 99999 7 -1
$ getent passwd blockeduser
blockeduser:x:1102:1102::/home/blockeduser:/usr/sbin/nologin

তিনটে দরজাই বন্ধ — password মিলবে না, shell login করতে দেবে না, আর account নিজেই মেয়াদোত্তীর্ণ। -e 1 মানে ১৯৭০-এর ২ জানুয়ারি, অর্থাৎ বহু আগেই শেষ। তবু home directory আর সব file অক্ষত আছে — পরে দরকার হলে ফেরত পাওয়া যাবে।

bash — solution
# ৩ — intern account
$ sudo useradd -m -s /bin/bash -c "Summer Intern" intern
$ sudo passwd intern

# ৩০ দিন পরের তারিখ হিসেব করে বসানো
$ sudo usermod -e "$(date -d '+30 days' +%F)" intern

$ sudo chage -M 15 intern
$ sudo chage -d 0 intern

$ sudo chage -l intern
output
Last password change                    : password must be changed
Account expires                         : Apr 01, 2026
Maximum number of days between password change : 15

$(date -d '+30 days' +%F) আজকের তারিখ থেকে ৩০ দিন পরের তারিখটা YYYY-MM-DD ছাঁচে বের করে দেয় — হাতে হিসেব করার দরকার নেই। macOS-এ এই লেখাটা আলাদা (date -v+30d +%F), তবে Linux-এ উপরেরটাই চলে।

ক্রমটা খেয়াল করো — chage -d 0 সবার শেষে। আগে দিলে passwd চালানোর সময় সেটা মুছে গিয়ে আজকের তারিখ বসে যেত।

Command গুলো এক নজরে

Commandকাজ
usermod -aG <group> <user>supplementary group-এ যোগ করে (-a ভুলো না)
usermod -g <group> <user>primary group বদলায়
usermod -s <shell> <user>login shell বদলায়
usermod -l <new> <old>username বদলায় (নতুন নাম আগে)
usermod -d <dir> -m <user>home directory বদলায় আর file সরায়
usermod -u <uid> <user>UID বদলায়
usermod -c "<text>" <user>comment / GECOS বসায়
usermod -e <YYYY-MM-DD> <user>account-এর মেয়াদ বসায়
usermod -L / -U <user>account lock / unlock করে
groupmod -n <new> <old>group-এর নাম বদলায়

আটকে গেলে

সমস্যাকী হয়েছে / কী করবে
user is currently used by process Nঐ user login করে আছে। sudo pkill -u <user> দিয়ে তার process বন্ধ করো, তারপর আবার চেষ্টা করো।
নাম বদলানোর পর user-এর file-এ ঢুকতে পারছে না-l home directory বদলায় না। sudo usermod -d /home/<new> -m <new> চালাও।
UID বদলানোর পর কিছু file-এ access নেইঐ file গুলো এখনো পুরোনো UID-র নামে। sudo find / -uid <পুরোনো> -not -path "/proc/*" 2>/dev/null দিয়ে খুঁজে chown করো।
usermod: group 'X' does not existGroup টা আগে বানাও — sudo groupadd X। RHEL/Fedora-তে sudo-র বদলে wheel।
passwd -S-এ NP দেখাচ্ছেAccount-এ কোনো password নেই। sudo passwd <user> দিয়ে একটা বসাও (Step 6)।
Account expired বলে login করতে দিচ্ছে নামেয়াদ চলে গেছে। sudo usermod -e "" <user> দিয়ে মেয়াদ তুলে নাও।
usermod -e-তে invalid dateছাঁচটা YYYY-MM-DD হতে হবে — 31-12-2025 নয়, 2025-12-31।
Lock করার পরও user SSH দিয়ে ঢুকছে-L শুধু password বন্ধ করে, key নয়। Shell-ও nologin করে দাও (Step 8-এর তিনটে command)।
groupdel: cannot remove the primary groupকারো primary group এটা। আগে ঐ user-কে মুছো বা তার primary group বদলাও।

পরিষ্কার করে ফেলা (ঐচ্ছিক)

bash — cleanup
# user গুলো মুছে দাও (home directory সহ)
$ sudo userdel -r newuser
$ sudo userdel -r customuser

# Challenge-এর user গুলো করে থাকলে
$ sudo userdel -r blockeduser
$ sudo userdel -r intern

# group মুছে দাও
$ sudo groupdel testgroup

# মিলিয়ে দেখো — কিছুই যেন না থাকে
$ getent passwd newuser customuser
$ getent group testgroup
userdel -r-এ ভুলে যাওয়া file পড়ে থাকতে পারে

-r শুধু home directory আর mail spool মোছে। ঐ user-এর বানানো যদি অন্য কোথাও file থাকে — যেমন /tmp বা /var-এ — সেগুলো পড়ে থাকবে, আর তাদের মালিক হবে এমন একটা UID যেটা আর কারো নয়। খুঁজে বের করতে:

bash
$ sudo find / -nouser -not -path "/proc/*" 2>/dev/null

-nouser মানে "এমন file যার মালিকের কোনো account নেই"।

শুধু নিজের practice machine-এ

userdel -r home directory সহ সব মুছে দেয়, ফেরানোর উপায় নেই। আর find / -exec chown-জাতীয় command গুলো ভুল UID দিয়ে চালালে system-এর file-এর মালিকানা নষ্ট হয়ে যেতে পারে — চালানোর আগে -exec অংশটা বাদ দিয়ে একবার দেখে নাও কোন কোন file ধরা পড়ছে।

Lab 5 — চেকলিস্ট
মূল কথা

User-এর সব তথ্য আসলে তিনটে সাধারণ text file-এ লেখা — /etc/passwd, /etc/shadow, /etc/group। usermod আর chage কোনো জাদু করে না, শুধু ঐ file গুলোর ঘর গুলো নিরাপদে বদলে দেয়। কোন command কোন file ছোঁয় — এটুকু মাথায় থাকলে পুরো user management নিজে থেকেই সহজ হয়ে যায়।

আর সবচেয়ে বড় শিক্ষাটা হলো — যা বদলাও, তা যাচাই করো। usermod সফল হলে কিছুই বলে না, তাই id, getent passwd বা chage -l চালিয়ে প্রতিবার মিলিয়ে নেওয়াটাই একজন admin-এর আসল অভ্যাস।
